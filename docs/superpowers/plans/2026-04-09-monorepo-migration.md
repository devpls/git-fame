# v0.2.0 Monorepo Migration Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Move the existing node-fame package into an npm workspaces monorepo at `packages/node-fame/` and scaffold the empty `packages/wasm-blame/` package, preserving all 303 tests and git rename history.

**Architecture:** npm workspaces with `packages/*` glob. Root holds shared tooling (husky, lint-staged, prettier). Each package owns its own tsconfig, eslint config, vitest config, and build. All source imports are relative and unchanged by the move.

**Tech Stack:** npm workspaces, TypeScript 6, ESLint 9 with `projectService`, vitest 4, zshy, husky 9.

**Commit style:** Single-line, plain English, no prefix, no Co-Authored-By.

- [ ] **Step 6: Create root package.json**

This is the workspace root. It is `private: true` (never published) and holds only shared tooling.

Create `package.json` at repo root:

```json
{
  "private": true,
  "workspaces": ["packages/*"],
  "scripts": {
    "prepare": "husky"
  },
  "lint-staged": {
    "packages/node-fame/**/*.{ts,js,cjs,mjs}": [
      "eslint --config packages/node-fame/eslint.config.ts --fix",
      "prettier --write"
    ],
    "*.{json,md,yml,yaml}": ["prettier --write"]
  },
  "devDependencies": {
    "husky": "^9.1.7",
    "lint-staged": "^16.4.0",
    "prettier": "^3.8.1"
  }
}
```

Key decisions:

- `lint-staged` scopes TS files to `packages/node-fame/**` and uses `--config` to point ESLint at the correct flat config. When `wasm-blame` gets its own code, add a second entry.
- `prettier` handles all JSON/MD/YAML files repo-wide.
- `husky`, `lint-staged`, `prettier` live here because they run from root (git hooks). Package-specific tools (eslint, typescript, vitest, zshy) live in each package.

- [ ] **Step 9: Edit packages/node-fame/eslint.config.ts**

  ...tseslint.configs.stylisticTypeChecked,

        projectService: true,

      '@typescript-eslint/no-misused-promises': 'error',

      '@typescript-eslint/no-unused-vars': [
        'error',
        { argsIgnorePattern: '^_', varsIgnorePattern: '^_' },
      ],

      'no-async-promise-executor': 'error',
      'no-duplicate-case': 'error',

- [ ] **Step 3: Create packages/wasm-blame/src/index.ts**

Types from the spec + a placeholder factory. The types match the spec's public API exactly. The factory throws so that node-fame's fallback path activates cleanly.

```ts
export interface WasmBlameHunk {
  linesInHunk: number;
  finalStartLine: number;
  authorName: string;
  authorEmail: string;
  authorTime: number;
  sha: string;
}

export interface WasmBlameOptions {
  followRenames?: boolean;
  ignoreWhitespace?: boolean;
  newestCommit?: string;
}

export interface WasmBlame {
  hunkCount(): number;
  hunkByIndex(i: number): WasmBlameHunk;
  free(): void;
}

export interface WasmRepository {
  blameFile(path: string, options?: WasmBlameOptions): WasmBlame;
  free(): void;
}

export interface WasmGit {
  repositoryOpen(path: string): WasmRepository;
  shutdown(): void;
}

export const loadWasmGit = async (): Promise<WasmGit> => {
  throw new Error('@node-fame/wasm-blame is not yet implemented');
};
```

```yaml
name: CI

on:
  push:
    branches: [main, feat/initial]
  pull_request:
    branches: [main]

jobs:
  node-fame:
    runs-on: ${{ matrix.os }}

    strategy:
      matrix:
        node-version: [20, 22]
        os: [ubuntu-latest, macos-latest]

    steps:
      - uses: actions/checkout@v4

      - name: Use Node.js ${{ matrix.node-version }}
        uses: actions/setup-node@v4
        with:
          node-version: ${{ matrix.node-version }}
          cache: npm

      - name: Install dependencies
        run: npm ci

      - name: Lint
        run: npm run lint -w packages/node-fame

      - name: Test
        run: npm run test:run -w packages/node-fame

      - name: Build
        run: npm run build -w packages/node-fame
```

Changes from current:

- Job renamed from `build` to `node-fame` (clearer in a multi-package repo).
- All three commands use `-w packages/node-fame` to scope to the workspace.
- `npm ci` stays at root (installs all workspaces).
